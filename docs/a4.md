  THE LOOP

  action → reduce(state, action) → new state + effects
                                        ↓           ↓
                                    UI updates   effects run
                                                     ↓
                                              (may send more actions)

  You define state. Things happen (actions). State changes (reduce).
  Work gets done (effects). UI reflects state. aio persists and syncs.

  YOUR APP — v0.7 three tiers (recommended)

  features/counter/index.ts   reactive() — plain methods (simplest, 80% of features)
                              flow()     — generators (multi-step workflows)
                              feature()  — reduce/execute (complex reactive logic)
  App.tsx                     useFeature() — scoped state, typed send
  app.ts                      aio.run({ features: [...] })

  Start reactive. Upgrade when you feel the pain, not before.

  ── v0.4 classic (still supported) ──

  state.ts      What's my data?          type + initial values
  actions.ts    What can happen?          action catalog
  effects.ts    What work needs doing?    effect catalog
  reduce.ts     How does data change?     (state, action) → { state, effects }
  execute.ts    How does work get done?   (app, effect) → void
  App.tsx       What does user see?       React component
  app.ts        Start.                    aio.run(initialState, config)

  PRODUCTION — compile:<shell>:<topology>

  Two axes: shell (what renders) × topology (local or remote).
  Local = self-contained, 127.0.0.1. Remote = exposed 0.0.0.0 or client-only.

  THREE TIERS (v0.7)

  reactive(name, {              plain methods — simplest (80% of features):
    state,                        initial state shape
    methods: { add(s, x) {} },    sync=Immer draft, async=live Proxy
    selectors: { total(s) {} },   derived values
    machine?,                     state machine guards (optional)
  })

  flow(trigger, function*(ctx) {  sequential workflows — generators:
    yield* ctx.call(name, fn)     async work + time-travel visibility
    yield* ctx.step(name, fn)     state mutation checkpoint
    yield* ctx.done()             terminal success
  })

  feature(name, {               full control — reduce/execute:
    state,                        initial state shape
    actions,                      action catalog (auto-prefixed)
    effects,                      effect catalog (auto-prefixed)
    machine,                      state machine (required)
    reduce(state, action, {A,E}), reducer (state is Immer draft)
    execute(app, effect, {E,A}),  executor (scoped dispatch)
    selectors,                    memoized derived state
    deps,                         other features this depends on
    init(app),                    called on startup (app: ScopedApp)
    destroy(app),                 called on shutdown (reverse order)
  })

  Direct calling (after aio.run):
    counter.increment(5)          dispatch — typed, no .A. needed
    counter.doubled()             selector — no state arg needed
    counter.A.increment(5)        action object (cross-feature, tests)

  A — dual role:  A.Increment = 'Counter:Increment'  (switch label)
                  A.increment(5) → { type, payload }  (creator)

  E — dual role:  E.Log = 'Counter:Log'  (switch label)
                  E.log('msg') → { type, payload }  (creator)

  Machine guards: action dropped if not in machine.states[current].on
  _status: auto-managed, never set manually, tracks current machine state
  Dead-end states (no outgoing transitions) warn at definition time

  Platform APIs in execute:
    Deno globals (Deno.readTextFile, etc.) — use directly, browser never calls execute
    Server-only imports — use dynamic import() inside execute, not top-level import
    Affects: Electron, browser, Android (CLI/service are unaffected)

  Cross-feature:
    1. Selectors — read another feature's derived state
    2. Listening — handle another feature's actions in your reducer
    3. bridge()  — request/response with timeouts, retries, circuit breaker

  Runtime:
    middleware: [logger(), validate(), metrics(), freeze(), perfBudget()]
    version: N + migrations: [(s) => newS]     state versioning
    app.features.enable/disable/status/health   feature registry
    GET /__health                                health endpoint
    --isolate=counter,dc                         dev-mode feature filter
    _source: 'UI' | 'Effect' | 'System' | 'Test'  action source tagging

  SCALING UP — file structure (see structure.md)

  src/
    app.ts              boot only — aio.run({ features })
    App.tsx             layout + routing only
    features/           one folder per feature
      counter/
        index.ts        reactive() or feature() — everything starts here
        types.ts        extracted at ~200 lines
        helpers.ts      pure functions
        reduce.ts       extracted at ~500 lines
        execute.ts      extracted at ~500 lines
        ui/             feature UI components
    shared/             code used by 2+ features (promote, don't pre-plan)
      types/            domain types (framework-agnostic)
      utils/            pure functions
      ui/               reusable components (no feature imports)

  Split when you feel the pain, not before.
  10+ features? Group by domain: features/trading/engine/, features/data/dc/
  Never nest deeper than one domain level.
