# Goals for aio framework

The vision: aio should be the most loved framework — the holy grail of
application development, so good that developers wouldn't want to build apps any
other way. The rules below are the checkable expression of that vision.

- aio framework should be super user friendly
- aio framework should be stupid-proof
- aio framework should be intuitive
- aio framework should be predictable
- aio framework should be forgiving
- aio framework should be minimalistic
- aio framework should be super easy and familiar
- aio framework should significantly simplify application development
- aio framework should free developers from any unnecessary complexity
- aio framework should be able to build electron app or android app with single
  command line
- aio framework should use compact and intuitive syntax
- aio framework should always provide detailed error descriptions so developer
  doesn't need to spend hours investigating root cause
- aio framework should be unified so it feels very consistent
- aio framework should be using air (aio renderer) as default react-lite-like ui
  framework
- aio framework should minimize/hide wiring syntax, boilerplate and all
  unnecessary code
- the latest two external field reports contain zero P1/P2 issues
  (loved-by-developers proxy)
- every breaking change ships in an alpha; beta and final releases never break
  existing apps
