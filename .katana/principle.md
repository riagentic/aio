# Major aio principles


## These are not really measurable criteria, but rather rules that must be followed

- aio framework is intuitive
- aio (surface) is compact 
- aio doesn't break surface compatibility (ie. old applictions keep running with new version)
- quality requests leading to breaking surface compatibility are saved in untracked/v2.md
- aio framework logs all real errors and warnings
- aio framework doesn't loglog artificial, false or unreal errors and warnings
- aio framework is helpful to developer, ie. is providing correct informationn, context and hints about issues and howto use aio correctly
- aio framework is not confusing (principles are clear)
- aio choses never makes life of developer harder than necessary 
- aio uses balanced approach "doable quality", ie. as high as possible quality that is still reasonably doable
- aio choses right, sound and robust architecture (as simple as effective as possible, avoiding overenginnering) 
- aio provides surface for user to build and maintain applications easily while making the hard stuff itself internally 
- aio has pefect onbording experience (ie. smooth, intuitive, flawless)
- aio has optimal facility for humans and for AI agents
- aio is using few clean concepts those it promotes accross the entire framework
- aio is not using incompatible approaches where it can use clean compatible and reusable approaches
- aio is trying to minimize its learning curve 
- aio provides reusable functionality that can be used by many various appplications
- aio refuses feture request that can be used only by one specific app and by no one else, such a feature belongs to the app, not to the framework
