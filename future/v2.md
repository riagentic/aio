# aio v2 — material found after the beta

Things that **should** be fixed but cannot be, because fixing them would break
surface compatibility. The surface froze on 2026-09-04, effective alpha77
(`docs/basics/semver-policy.md`): an app that compiles and runs against
v1.0.0-alpha76 does so against every later alpha, every beta, and 1.0.0. So when
a fix turns out to need a break, it is written down here and the additive
workaround ships instead.

Each entry records four things, because a note that only says "this is wrong" is
unusable a year later: what is wrong and where · what shipped instead · what v2
should do · what it would break.

Severity: 🔴 correctness/data · 🟠 design debt that compounds · 🟡 papercut.

> Material from before the beta lives in `untracked/aio-v2.md`, which is
> gitignored. This file is the tracked home from 1.0.0-beta on.

---

## 1. 🟠 `TestUI`'s index signature defeats `am testgen`'s headline promise

**What is wrong.** `src/testing/ui-testgen.ts`'s module header promises that "a
renamed button breaks tests at compile time". It does not. `TestUI` and
`UIComponentHandle` both carry `[name: string]: any`, and the generated
interfaces extend/intersect them, so every typo type-checks:

```
ui.App.SubmitButtonThatDoesNotExist.click();   // deno check: passes
ui.CompletelyBogusName.click();                // deno check: passes
```

Generated types also omit the ordinal forms (`Row2`) the runtime requires for a
second instance, so the types and the runtime disagree in both directions.

**What shipped instead.** Nothing yet. Autocomplete does improve, which is why
the gap survived: the feature looks like it works.

**What v2 should do.** Drop the index signature from `TestUI` and
`UIComponentHandle`, and have `testGen` emit the ordinal members it knows the
runtime will accept. Then a renamed button really is a compile error.

**What it would break.** Every test that addresses a handle the generator did
not emit — which is every test written without `testgen`, i.e. most of them.
That is why it is a major.

## 2. 🟠 `checkCells` takes `(state, config, baseDir)`, not `(cells)`

**What is wrong.** The name says cells; the signature is
`lint(state, config, baseDir, prod, headless, useElectron, uiEntry,
headlessClient?)`.
Its own doc comment and `api-reference.md` both said `checkCells(cells)` — the
form a reader would guess from the name — and that throws on `config.reduce`.

**What shipped instead.** Both docs corrected to the real signature, and
`tests/phase4-extras.test.ts` now calls the documented form so it cannot drift
again.

**What v2 should do.** Make the name honest: `checkCells(cells)` composes the
cells itself and returns the same findings.

**What it would break.** Every existing caller, and the `Lint` return shape if
the composition changes what it can see.

## 3. 🟡 `set-add` / `set-remove` converge on MEMBERSHIP, not on ORDER

**What is wrong.** Each pairwise merge picks its canonical layout from THAT
PAIR's clocks, which makes the merge symmetric — the property two screens depend
on — but the merged value carries no clock of its own, so three peers folding
the same merges in different orders reach the same members in different orders.
Measured and shrunk in `tests/sync/properties/set-convergence.test.ts`.

**What shipped instead.** The property is pinned (18,000 randomised three-peer
folds prove membership converges; the order difference is pinned as real), and
`docs/persistence/crdt.md` says "Members" with a footnote instead of "Yes". It
is transient in the engine as it stands: a merged value reaches only the
optimistic client view and the server remains the convergence authority.

**What v2 should do.** Give a merged value a clock of its own, or order by a
value-intrinsic key.

**What it would break.** Ordering by a value key throws away the list order
every app renders; a per-value clock is a wire change.

## 4. 🟡 An app's identity still collapses two names that differ only in ASCII punctuation

**What is wrong.** `slugify` maps every non-alphanumeric run to `-`, so
`my-app`, `my_app`, `my.app` and `My App` are ONE app — one data directory, one
lock, one UDS socket, one shared-key cookie. The file states this as a
consequence rather than a defect, and for punctuation it is defensible.

**What shipped instead.** The half that was not defensible is fixed: a non-ASCII
name (where the slug dropped whole letters, so "Über" and "Ber" were both `ber`
and two CJK-named apps were both `aio-app`) now carries a short hash of the
original. Pure-ASCII ids are byte-identical to before.

**What v2 should do.** Either require an explicit `appId` whenever the derived
slug is not a faithful round-trip, or hash every name.

**What it would break.** Every app's data directory, lock path, socket path,
cookie name and compiled binary name — i.e. every installed app's data.

## 5. 🟡 A control's surface name ignores text nested one element down

**What is wrong.** `<button><span>Save</span> <b>draft</b></button>` and
`<input type="submit" value="Send">` get the bare numbered role (`Button3`)
while the docs say the label comes from the visible text. Every icon-plus-label
button in a kit hits it.

**What shipped instead.** The docs now say "own text", and point at `t` /
`aria-label`. A post-beta fix that read nested text was written and reverted:
naming one element renumbers every later unnamed sibling (`Button2` becomes
`Button`), and existing tests and `am trigger` paths address those by number.

**What v2 should do.** Read name-from-content text (ARIA's rule) for
button/link/tab/menuitem/option roles and a submit input's `value`.

**What it would break.** Every numbered name after the first newly-named control
in a component.

## 6. 🟠 With `auth: true`, a project file with an image/HTML/JS extension is readable without signing in

**What is wrong.** The anonymous gate decides by file EXTENSION: shell-shaped
files (`.png`, `.html`, `.js`, fonts…) are served before sign-in so the sign-in
page can have its logo, CSS and script. So `/uploads/passport.png`,
`/report.html` and `/data/dump.js` under the app directory are served to anyone.

**What shipped instead.** `.txt` is no longer anonymous (only `robots.txt` /
`humans.txt` are), `/.well-known/` is explicitly public, and `docs/auth/auth.md`
says never to write private uploads into the app directory — use the blob store,
which is always authenticated.

**What v2 should do.** Serve anonymously only what the built client bundle
references, plus a declared public directory; everything else needs a session.

**What it would break.** Any `auth: true` app whose sign-in page (or a public
page) uses a static file not reachable from the bundle and not moved into the
declared public directory — `tests/auth-anon-surface.test.ts` pins `/logo.png`
and `/index.html` as public today.

## 7. 🟠 A sync method's randomness/clock is re-run per replica

**What is wrong.** Every replica (each tab, the server) re-runs a sync method
when it folds the op, so `crypto.randomUUID()` or `Date.now()` inside the method
yields a different value on each — ids fork and a later `remove(id)` silently
does nothing on the server.

**What shipped instead.** The docs Quick Start passes the id in as an argument
and `docs/persistence/crdt.md` says methods must be deterministic; the browser
engine folds twice, logs a method that disagrees with itself (once per method)
and asks the server for a snapshot of that cell. A same-millisecond `Date.now()`
is not caught.

**What v2 should do.** Record nondeterministic values per op id the first time
the method runs and replay them on every replica, server dispatch and boot
replay included.

**What it would break.** The op wire format and the journal format.

---

## 8. 🟡 A `merge:` strategy's result is view-only, so the overwritten peer is never told

**What is wrong.** `merge: { body: "text" }` merges both edits in the client's
view, but the server keeps the later op's value; the peer whose edit lost gets
no callback.

**What shipped instead.** `onConflict` now fires on the reconnect catch-up path
too, the engine warns once per field when the merged value is not what the
server will keep, and the docs say merges exist only in the client's view.

**What v2 should do.** Ops carry `base` (the confirmed position they were made
at); the server keeps a short window of states, merges merge-strategy fields
against the state at `base`, and pushes the result.

**What it would break.** The sync op wire format.
